# 怎么验证这个东西真的成功了

这份文档回答一个问题：**你怎么知道它成了？** 它不要求你会写代码，也不要求你懂音频，你只需要照着下面的步骤一步步做，每一步都写清了"要做什么"和"看到什么才算过"。最后你会得到一个是或否的结论。如果你是第一次拿到这个安装包，建议从头按顺序做完全部四步；如果你只是想快速确认它没坏，直接跳到第三步。

## 开始之前

你需要准备：

- 一台已经 root（KernelSU）的手机，本项目在 realme RMX5010 / ColorOS 16 上验证；
- 手机上装好了 LSPosed；
- 至少一个音乐软件（默认用网易云音乐做验证）；
- 一个能和队友语音的游戏，或者任何能录音的 App；
- 一个能听你说话的队友，或者你自己用另一台设备放音。

**重要前提**：当前版本的代码送进麦克风的还**不是真实音乐，而是一段固定的测试音**（一个持续的音，类似电话拨号音）。这是有意的中间步骤，用来先确认"声音能不能被替换"这个根本问题。因此下面的验证里，判断标准是"能不能听到那个测试音"，而不是"能不能听到歌"。等换成真实音乐后，判断标准才变成"能听到歌"。

## 第零步：确认模块已被框架加载

这一步是后面所有验证的前提，**必须先做**。

- **在哪执行**：手机上的 LSPosed 管理器界面（应用名通常是 LSPosed，图标是一个方块）。
- **执行什么**：打开管理器，找到模块列表，确认列表里能看到本工具（名称"麦克风控制"），并把它的开关打开、勾选你要测试的目标应用。
  - 如果列表里**看不到**本工具：说明框架还没扫描到它。框架只在开机时扫描一次模块，所以新装的模块需要**重启一次手机**才会出现。
- **看到什么算成功**：模块列表里有本工具且处于启用状态，作用范围里包含你要测的那个应用（比如王者荣耀）。
- **不过怎么办**：见 [runbook.md](runbook.md) 症状一第 3 项。

## 第一步：确认基础环境还在

- **在哪执行**：手机上的 Termux 终端（任何目录都可以）。
- **执行什么**：`su -c id`
- **看到什么算成功**：输出里出现 `uid=0(root)`。
- **不过怎么办**：说明 root 出了问题，先别往下做，去看 [runbook.md](runbook.md) 症状一。
- **为什么查**：整个工具依赖 root 才能改音频路由，这一步不过，后面全是白做。

## 第二步：确认中转站设备还在

- **在哪执行**：同样在 Termux 终端。
- **执行什么**：`su -c 'service list | grep r_submix'`
- **看到什么算成功**：输出里出现一行含 `r_submix` 的内容。
- **不过怎么办**：说明这台手机没有提供这个关键设备，当前方案走不通，见 [runbook.md](runbook.md) 症状一第 2 项。
- **为什么查**：声音中转全靠它。换手机或系统升级后它有可能消失。

## 第三步：核心功能验证（最重要的一步）

这一步验证"目标应用到底读到了什么"。

**要做什么**：

1. 打开本工具的界面，把开关**打开**；
2. 在界面的应用列表里，选中你的音乐软件；
3. 进入游戏（或打开录音机），发起一次语音/录音；
4. 对着麦克风位置**不要说话**，可以故意在旁边制造点声音（比如拍手、说话）；
5. 问队友，或者回放录音，判断听到的是什么。

**看到什么算过**：

| 实际情况 | 结论 |
| --- | --- |
| 听到那段测试音，听不见环境声 | **通过**——说明替换生效，链路是通的 |
| 听到测试音，但也能隐约听见环境声 | **降级通过**——替换生效但没完全盖住，记录到问题里 |
| 什么都听不到，或者听到的还是环境声 | **不通过**，看 [runbook.md](runbook.md) |
| 能听见游戏里的枪声或队友自己的声音 | **不通过**，这是回音问题，看 [runbook.md](runbook.md) |

**换成真实音乐之后**，判断标准相应改为"听到的是歌"。

## 第四步：确认关掉以后能恢复

**要做什么**：

1. 在界面上把开关**关闭**；
2. **不重启游戏，不重启手机**；
3. 对着麦克风正常说话，问队友能不能听见你。

**看到什么算过**：队友能正常听见你说话，且听不见歌了。

**为什么**：这说明开关是即时生效的、可逆的。这一条不过的后果很严重——意味着你一旦打开就关不掉，所以务必测。

## 附加验证：不依赖队友的自测方法

如果手边没有队友，可以自己验证。这个方法还能顺便留一份能回放的证据。

- **在哪执行**：手机上的系统录音机（或任意录音 App），不需要电脑。
- **执行什么**：在开关打开、正在放歌的状态下，录一段 10 秒左右的音；然后关掉开关，再录一段同样的时长。
- **看到什么算成功**：第一段录音里是歌，第二段录音里是你周围的环境声。两段明显不同，说明开关真的起作用了。
- **说明**：这个方法和"队友听见什么"的原理是同一套，所以可以互相替代。注意部分录音 App 自带降噪，可能影响判断，优先用系统自带录音机。

**已知限制**：开发机 Termux 里虽然装了 ffmpeg，但它不带安卓的音频输入设备（实际确认过，`ffmpeg -devices` 里只有虚拟滤镜输入），所以**不要**尝试用 ffmpeg 在命令行直接录麦克风，那条路走不通。

## 判定标准汇总

| 档位 | 判据 | 是否算成功 |
| --- | --- | --- |
| 第一档 | 队友听见歌，完全听不见环境声 | 是，最佳结果 |
| 第二档 | 队友听见歌，环境声残留但很微弱 | 是，可接受 |
| 失败 | 听不见歌，或听见游戏音效/回音 | 否 |

关于延迟：**不设硬性指标**。判断标准只有一条——队友那边听到的歌是不是连续、不卡顿、不中断。连续可听即为通过。
