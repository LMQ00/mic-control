# 怎么验证这个东西真的成功了

这份文档回答一个问题：**你怎么知道它成了？** 它不要求你会写代码，也不要求你懂音频，你只需要照着下面的步骤一步步做，每一步都写清了"在哪做、做什么、看到什么才算过"。最后你会得到一个是或否的结论。如果你是第一次拿到这个安装包，建议从头按顺序做；如果你只是想快速确认它没坏，直接跳到第三步。

## 开始之前

你需要准备：

- 一台已经 root（KernelSU）的手机，本项目在 realme RMX5010 / ColorOS 16 上验证；
- 手机上装好了 LSPosed；
- 至少一个音乐软件（验证时用的网易云音乐）；
- 一个能和队友语音的游戏（验证时用的王者荣耀）；
- 一个能听你说话的队友，或者你自己用录音的方式验证。

**两个前提，请先知道**：

1. 现在的代码送进麦克风的**就是你实际在放的那首歌**，所以判断标准是"队友能不能听到你放的歌"。
2. 模块需要**重启一次手机**才会被框架加载（框架只在开机时扫描模块）。所以第一次验证之前要先重启。第零步就是确认这件事。

## 第零步：确认模块已被框架加载

这一步是后面所有验证的前提，**必须先做**。

- **在哪执行**：手机上的 LSPosed 管理器界面。
- **执行什么**：打开管理器，进入模块列表，确认能看到本工具（名称"麦克风控制"），把它的开关打开，并且**在作用范围里勾选你要测试的应用**——音乐软件和游戏都要勾上，缺一个都不行。
  - 如果列表里**看不到**本工具：说明框架还没扫描到它，**重启一次手机**再看。这是框架的既定机制，不是故障。
- **看到什么算成功**：模块列表里有本工具、处于启用状态，作用范围里同时包含你的音乐软件和游戏。
- **不过怎么办**：见 [runbook.md](runbook.md) 症状一第 3 项。

## 第一步：确认 root 还在

- **在哪执行**：手机上的 Termux 终端（任何目录都可以）。
- **执行什么**：`su -c id`
- **看到什么算成功**：输出里出现 `uid=0(root)`。
- **不过怎么办**：说明 root 出了问题，先别往下做，去看 [runbook.md](runbook.md) 症状一。
- **为什么查**：整套机制依赖 root 才能插手应用的声音，这一步不过，后面全是白做。

## 第二步：确认界面能正常用

- **在哪执行**：手机桌面上点开本工具。
- **执行什么**：看界面是否正常显示；把顶部开关打开；在下面的列表里选中你的音乐软件。
- **看到什么算成功**：界面上有一个总开关和一个应用列表；开关能拨动；列表里能找到并选中你的音乐软件。
- **不过怎么办**：如果列表是空的，说明读取应用列表的权限没生效，见 [runbook.md](runbook.md)。

## 第三步：核心功能验证（最重要的一步）

这一步验证"队友到底听见了什么"。

**要做什么**：

1. 确认界面上的总开关是**打开**的；
2. 确认列表里已经选中你的音乐软件；
3. 戴上耳机，开始放歌（音乐照常从耳机里响，这是正常的）；
4. 进入游戏的语音房间；
5. 对着麦克风位置**不要说话**，可以故意在旁边制造点声音（拍手、说话）作为对照；
6. 问队友两个问题：**能听见我放的歌吗？能听见我这边的环境声吗？**

**看到什么算过**：

| 队友的回答 | 结论 |
| --- | --- |
| 能听见歌，听不见环境声 | **通过**，而且是最好的情况 |
| 能听见歌，但也能隐约听见环境声 | **降级通过**，可用，但请记录这个现象 |
| 听不见歌 | **不通过**，看 [runbook.md](runbook.md) 症状一 |
| 能听见歌，但同时也听见游戏里的枪声或队友自己的声音 | **不通过**，这是回音问题，看 [runbook.md](runbook.md) 症状二 |

**顺带确认一件事**：你自己戴耳机听到的歌应该是完全正常的，不受影响。如果连你自己听歌都出问题了，也属于故障。

## 第四步：确认关掉以后能恢复

这一步同样重要，务必做。

**要做什么**：

1. 在界面上把开关**关闭**；
2. **不重启游戏，不重启手机**；
3. 对着麦克风正常说话，问队友能不能听见你。

**看到什么算过**：队友能正常听见你说话，并且听不见歌了。

**为什么必须测**：这说明开关是即时生效、可以回退的。这一条不过的后果比较严重——意味着你一旦打开就没法关掉，所以务必验证。

## 附加验证：不依赖队友的自测方法

如果手边没有队友，可以自己验证。

- **在哪执行**：手机上的系统录音机（或任意录音 App），不需要电脑。
- **执行什么**：在开关打开、正在放歌的状态下，录一段 10 秒左右的声音；然后关掉开关，再录一段同样时长。
- **看到什么算成功**：第一段录音里是歌，第二段录音里是你周围的环境声。两段内容明显不同，说明开关确实起作用了。
- **说明**：这个方法和"队友听见什么"是同一套原理，可以互相替代。注意部分录音 App 自带降噪，可能影响判断，优先用系统自带录音机。

**已知限制**：用 `MediaRecorder` 录音的应用（很多系统录音机属于此类）不在覆盖范围内，可能测不出效果，这属于已知限制而不是配置错误。另外，开发机 Termux 里虽然装了 ffmpeg，但它不带安卓的音频输入设备（实际确认过），所以**不要**尝试用 ffmpeg 在命令行直接录麦克风，那条路走不通。

## 判定标准汇总

| 档位 | 判据 | 是否算成功 |
| --- | --- | --- |
| 第一档 | 队友听见歌，完全听不见环境声 | 是，最佳结果 |
| 第二档 | 队友听见歌，环境声残留但很微弱 | 是，可接受 |
| 失败 | 听不见歌，或听见游戏音效/回音 | 否 |

关于延迟：**不设硬性指标**。判断标准只有一条——队友那边听到的歌是不是连续、不卡顿、不中断。连续可听即为通过。
