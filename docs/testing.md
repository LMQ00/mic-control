# 怎么验证它真的成功了

## 开始之前

需要准备：

- 一台已经 root（KernelSU）的手机，本项目在 realme RMX5010 / ColorOS 16 上验证；
- 一个音乐软件（验证时用网易云音乐）；
- 一个能语音的游戏（验证时用王者荣耀），或者任意录音应用；
- 一个能听你说话的队友，也可以自己录音验证。

判断标准是「队友能不能听到你放的歌」。送进麦克风的就是你实际在放的那首。

## 第一步：给本应用授权 root

**在哪做**：KernelSU 管理器界面。

**执行什么**：打开管理器 → 超级用户列表，找到「麦克风控制」，把开关打开。

**看到什么算成功**：列表里本工具处于已授权状态。

**不过怎么办**：没授权时，界面上的开关拨了会提示「操作没成功」，工具不会生效。这一项不过，后面全是白做。

**顺带确认终端也有 root**：在 Termux 里执行 `su -c id`，输出里有 `uid=0(root)`。

## 第二步：确认界面能正常用

**在哪做**：手机桌面上点开本工具。

**执行什么**：把顶部开关打开；应用多时先在列表上方的搜索框里输入名称或包名，列表只剩匹配的；在列表里选中你的音乐软件。

**看到什么算成功**：开关能拨动；界面显示「已打开」；搜索后列表只剩匹配的应用，能选中你的音乐软件。开关打开后若显示「操作没成功：…」，把提示记下来。

**顺带看通知栏**：开关打开后，下拉通知栏能看到本工具的常驻通知，上面有一个「关闭」按钮，点它能直接关掉。

## 第三步：确认钩子真的装上了

**在哪做**：Termux 终端。

**执行什么**：

```
su -c '/data/data/com.lmq.miccontrol/files/mcinject status /data/misc/audioserver/libmcpayload.so'
```

**看到什么算成功**：输出形如「启用中 采集=… 注入=… 音轨=…」。

**补充**：界面上把开关关掉后再执行同一条命令，应输出「未启用」。

**不过怎么办**：见 [runbook.md](runbook.md) 症状一。若提示找不到文件，先在界面上把开关打开一次。

## 第四步：核心功能验证（最重要）

这一步验证「队友到底听见了什么」。

**要做什么**：

1. 确认界面上的总开关是**打开**的；
2. 戴上耳机开始放歌（歌从耳机里正常响，这是对的）；
3. 进游戏的语音房间；
4. 对着麦克风位置**不要说话**，在旁边拍手或说话作对照；
5. 问队友两个问题：**能听见我放的歌吗？能听见我这边的环境声吗？**

**看到什么算过**：

| 队友的回答 | 结论 |
| --- | --- |
| 能听见歌，听不见环境声 | **通过** |
| 能听见歌，也能隐约听见环境声 | **降级通过**，可用，记录这个现象 |
| 听不见歌 | **不通过**，见 [runbook.md](runbook.md) 症状一 |
| 能听见歌，同时听见游戏枪声或队友自己的声音 | **不通过**，这是回音，见症状二 |

**顺带确认**：你自己戴耳机听到的歌应该完全正常。

## 第五步：确认关掉以后能恢复

同样重要，务必做。

**要做什么**：

1. 在界面上把开关**关闭**；
2. **不重启游戏、不重启手机**；
3. 对着麦克风正常说话，问队友能不能听见你。

**看到什么算过**：队友能正常听见你说话，且听不见歌了。

## 不依赖队友的自测方法

手边没队友时，用录音自己验证。

**在哪做**：手机上的录音应用。

**执行什么**：开关打开、正在放歌时录 10 秒；关掉开关，再录 10 秒。

**看到什么算成功**：第一段录到的是歌，第二段是你周围的环境声。两段内容明显不同。

**说明**：部分录音应用自带降噪，可能影响判断，优先用系统自带的。

## 命令行自测（开发用）

需要一段可复现的录音。这一步不需要放歌，工具自己往环形缓冲填一段 440 赫兹正弦。

**执行什么**：

```
su -c '/data/data/com.lmq.miccontrol/files/mcinject on /data/misc/audioserver/libmcpayload.so 10383'
su -c '/data/data/com.lmq.miccontrol/files/mcinject sine /data/misc/audioserver/libmcpayload.so 440 1000000 48000'
su -c '/data/data/com.lmq.miccontrol/files/mcinject st /data/misc/audioserver/libmcpayload.so'
```

第三条输出每条录音流的速率、步长、声道和次数。缓冲写入速率为 48000 时，48000 赫兹的流步长 1.0000，16000 赫兹的流步长 3.0000。

**核心判据**：用系统录音机录 6 秒，导出录音，按 16 位整数、48000 赫兹解读。这一段实测：

| 指标 | 实测值 |
| --- | --- |
| 音高 | 440 赫兹 |
| 波形幅度（均方根） | 0.70 |
| 左右声道是否一致 | 一致 |
| 声道数（`mcinject st` 的声道列） | 2 |

通过时波形是单一频率的正弦，音高与填入的频率一致。

## 换了机型要重新求地址

工具的库内地址按本机实测值写死，换机型要重新测两个地址：

| 关口 | 找什么 |
| --- | --- |
| 出口 | `libaudioflinger.so` 里 `Track::getNextBuffer` 的地址 |
| 入口 | `libaudiohal@aidl.so` 里 `StreamInHalAidl::read` 的地址 |

做法：用带调试符号的同一份库，读出这两个函数的地址，填进 `native/mcpayload.c` 顶部的 `CAP_OFF` 与 `INJ_OFF`。

## 判定标准汇总

| 档位 | 判据 | 算不算成功 |
| --- | --- | --- |
| 第一档 | 队友听见歌，完全听不见环境声 | 算，最好 |
| 第二档 | 队友听见歌，环境声残留但很微弱 | 算，可接受 |
| 失败 | 听不见歌，或听见游戏音效、回音 | 不算 |

关于延迟：**不设硬指标**。只看队友听到的歌是不是连续、不卡顿、不中断。
