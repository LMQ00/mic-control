# 出问题了先查这里

这份文档是排查手册。遇到"装了没反应""队友听不见歌""开关关不掉"这类情况时，直接在这里按症状找到对应小节，照着做即可。每一条都写明先查什么、怎么判断、判断完往哪个方向处理。建议从上往下按顺序排查，前面的环节往往是后面症状的来源。

## 症状一：开关打开后，队友完全听不见歌

按顺序查这四项，任何一项不过就先解决它：

**1. 查 root 还在不在**

- **在哪执行**：手机上的 Termux 终端（任何目录都可以，不需要切到特定文件夹）。
- **执行什么**：`su -c id`
- **看到什么算成功**：输出里出现 `uid=0(root)`。
- **不过怎么办**：说明 root 环境有问题，检查 KernelSU 是否正常、是否给本工具授权了 root。

**2. 查模块有没有被启用**

- **在哪执行**：手机上的 LSPosed 管理器界面。
- **执行什么**：打开管理器 → 模块列表，确认本工具（"麦克风控制"）存在、开关已打开，并且**作用范围里同时勾选了音乐软件和游戏**。两个都要勾，只勾一个不会生效。
- **看到什么算成功**：模块在列表里、处于启用状态、作用范围含这两个应用。
- **不过怎么办**：
  - 如果列表里**看不到**本工具：这是最常见的情况。框架只在**开机时扫描一次**模块，新装的模块要**重启一次手机**才会出现在列表里。注意是重启手机，不是重启应用。
  - 如果能看到但没启用：打开它并勾选两个应用；改完作用范围后需要重启这两个应用（游戏要重启游戏）才生效。

**3. 查音乐软件有没有被正确选中**

确认界面上选中的音乐软件，和实际在放歌的是同一个。选了 A 却在用 B 放歌，结果就是静音。

**4. 查目标应用用的是哪种接口**

这是一个容易忽略但很关键的点：

- 用 `AudioRecord` 读麦克风的（王者荣耀这类游戏属于此类）——**在覆盖范围内**；
- 用 `MediaRecorder` 的（很多系统的录音机属于此类）——它的声音数据不经过工具能插手的那一层，**覆盖不到**。

如果前面三项都没问题，但录音机这类应用依然听不到歌，先确认它是不是用了 `MediaRecorder`。如果是，那属于已知的覆盖范围限制，不是配置错误。

**5. 查音乐软件是否真的在播放**

工具截取的是音乐软件交给系统的声音。如果歌根本没在放，自然没有东西可送。确认歌确实在播放、耳机里能听到。

## 症状二：队友听见歌，但同时也听见游戏里的枪声或队友自己的声音（回音）

这是**截取范围没有限定**造成的，也就是把不止一个应用的声音都送了出去。

**先查**：界面里是否确实选中了唯一一个音乐软件。

**还要查**：有没有别的 App 在同时播放声音（比如后台挂着的视频、系统提示音）。这些声音也会一起被送出去。

**说明**：这个症状正是"必须指定音乐软件"这个设计要解决的问题。如果确认已经指定了正确的软件、且没有其他 App 在放声音，却依然有回音，那就属于实现层面的缺陷，需要当作 bug 处理。

## 症状三：关掉开关后，队友还是听不见我说话

这是**最需要重视的症状**，意味着真实麦克风没有恢复。

**要做什么**：

1. 先重启一次游戏或重启手机，看是否恢复；
2. 恢复后，重新打开开关再关一次，看是否能复现；
3. 如果能稳定复现，停止使用，这是必须修的缺陷——一个关不掉的工具是危险的。

**重要程度**：参考 [security.md](security.md) 第四节，"关不掉"被明确列为真实风险。

## 症状四：歌能听见，但断断续续、卡顿

**先查**：手机是否处于低电量模式或省电模式。省电策略会限制后台进程，可能影响音频处理。

**再查**：是不是同时在跑很多占用资源的应用（比如游戏本身已经很吃性能）。

**说明**：本项目**不设延迟硬指标**，判断标准是连续可听。偶发一两次卡顿可以接受，持续卡顿则视为不通过。

## 症状五：云端编译失败（Actions 出现红叉）

**要做什么**：点进失败的那次运行，看报错日志的最后几十行。

常见原因与处理：

| 现象 | 大概率原因 | 处理 |
| --- | --- | --- |
| 提示找不到签名相关信息 | 加密变量没配或名字不对 | 回 [development.md](development.md) 第五节重新配置，注意变量名要和配置里一致 |
| 提示依赖下载失败 | 网络波动 | 在 Actions 页面手动重跑一次 |
| 提示某行代码语法错误 | 代码写错了 | 看日志指出的文件与行号，改掉 |

## 症状六：装不上，提示签名不一致

**原因**：新安装包和手机上已装的那个，签名不是同一个。

**处理**：卸载手机上的旧版本，再安装新的。

**说明**：这是安卓的正常限制，不是缺陷。但要注意卸载会清掉工具的设置（比如你选过的音乐软件），需要重新选一次。想要避免这种情况，就必须始终使用同一套签名——本项目已经配置好了固定签名，所以正常情况下不会再遇到这个问题，见 [development.md](development.md) 第五节。

## 症状七：换了另一台手机后不管用

**先查**：新手机上重新做一遍症状一的第 1、2 项，确认 root 正常、模块已被框架加载并且勾选了目标应用。

**说明**：本项目只在 realme RMX5010 / ColorOS 16 上实测过。换机后即使前面的前提都满足，也可能因目标应用内部接口不同而失效。先按症状一完整排查，把结果记录下来再决定怎么办，不要直接改代码。

## 症状八：模块装了但框架似乎"看不见"它

**表现**：管理器的模块列表里没有本工具，或者框架状态显示已加载模块数为 0。

**结论**：框架只在**开机时扫描一次**模块清单。新装的模块必须**重启一次手机**才会被登记和加载。

**一个必须避开的错误做法**：想通过"手动重启框架的守护进程"来触发重扫。**不要这么做。** 守护进程与系统之间的连接是在开机过程中建立的，中途单独重启守护进程不会重建这条连接，反而会让框架进入"未连接系统、已加载模块数归零"的状态，只能靠重启手机恢复。本项目的开发过程中实际踩过这个坑。

**正确做法**：老老实实重启一次手机。

## 症状九：在框架里新勾了一个应用，但它不生效

**表现**：你在模块作用范围里新勾了一个应用（比如把测试用的聊天软件加进来），但它在开关打开时毫无反应、声音照旧。

**结论**：和模块本身一样，作用范围也只在**开机时读一次**。新勾选的应用要等下次开机才会被纳入。

**正确做法**：重启一次手机再试。若重启后仍然不生效，按症状一排查。

**说明**：这一条容易被误判成"工具坏了"。判断方法很简单——早已勾选的应用（比如音乐软件）如果同时是正常的，那就说明工具本身没问题，只是新勾的那个还没生效。

## 症状十：通知栏看不到那个快捷开关

**表现**：界面上的开关已经打开，但下拉通知栏找不到本工具的通知。

**按顺序查**：

1. **通知权限是否被拒**：到系统设置里的应用通知权限，确认本工具的通知是允许的。较新的系统会弹窗询问，如果当时点了拒绝，通知就不会出现。
2. **开关是否真的打开了**：通知只在开关打开时挂出，关掉后会主动撤走。若你关过开关，这是正常现象。
3. **是不是被系统清理了**：部分系统会对长时间不活动的通知做收纳。下拉展开"静默通知"一类的分组看看。

**这一项不影响主要功能**：即使通知栏没有快捷开关，回到应用界面操作开关完全一样，功能不受影响。

## 收集信息再求助

如果排查完还是没有头绪，把这些信息收集齐，能极大加快定位：

1. 手机型号与系统版本；
2. 症状一里前四项的检查结果；
3. 具体症状（哪一步、期望什么、实际什么）；
4. 如果是编译问题，附上 Actions 的报错日志。
