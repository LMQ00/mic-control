# 出问题了先查这里

这份文档是排查手册。当你遇到"装了没反应""队友听不见歌""开关关不掉"这类情况时，不用重新读一遍原理，直接在这里按症状找到对应小节，照着做即可。每一条都写明了先查什么、怎么判断、以及判断完之后该往哪个方向处理。建议从上往下按顺序排查，因为很多表面症状的根因都在前面的环节。

## 症状一：开关打开后，队友完全听不见歌

按顺序查这四项，任何一项不过就先解决它：

**1. 查 root 还在不在**

- **在哪执行**：手机上的 Termux 终端（任何目录都可以，不需要切到特定文件夹）。
- **执行什么**：`su -c id`
- **看到什么算成功**：输出里出现 `uid=0(root)`。
- **不过怎么办**：说明 root 环境有问题，检查 KernelSU 是否正常、是否给本工具授权了 root。

**2. 查中转站设备还在不在**

- **在哪执行**：同样在 Termux 终端。
- **执行什么**：`su -c 'service list | grep r_submix'`
- **看到什么算成功**：输出里出现一行含 `r_submix` 的内容。
- **不过怎么办**：说明这台手机没提供这个设备，当前方案在你这台机器上不可行。这种情况请记录下来，需要换思路，不是改改配置能解决的。

**3. 查模块有没有被启用**

确认 LSPosed 里本模块处于启用状态，并且**作用范围包含目标 App**。改完作用范围后需要重启目标 App（游戏中要重启游戏），改动才会生效。

**4. 查音乐软件有没有被正确选中**

确认界面上选中的音乐软件，和实际在放歌的是同一个。选了 A 却在用 B 放歌，结果就是静音。

## 症状二：队友听见歌，但同时也听见游戏里的枪声或队友自己的声音（回音）

这是**捕获范围没有按 App 限定**造成的，也就是把整机正在播放的声音都送了出去。

**先查**：界面里是否确实选中了唯一一个音乐软件。

**还要查**：有没有别的 App 在同时播放声音（比如后台挂着的视频、系统提示音）。这些声音也会一起被送出去。

**说明**：这个症状正是"必须指定音乐软件"这个设计要解决的问题。如果确认已经指定了正确的软件、且没有其他 App 在放声音，却依然有回音，那就属于实现层面的缺陷，需要当作 bug 处理。

## 症状三：关掉开关后，队友还是听不见我说话

这是**最需要重视的症状**，因为它意味着真实麦克风没有恢复。

**要做什么**：

1. 先重启一次游戏或重启手机，看是否恢复；
2. 恢复后，重新打开开关再关一次，看是否能复现；
3. 如果能稳定复现，停止使用，这是必须修的缺陷——一个关不掉的工具是危险的。

**为什么重要**：参考 [security.md](security.md) 第四节，"关不掉"被明确列为真实风险。

## 症状四：歌能听见，但断断续续、卡顿

**先查**：手机是否处于低电量模式或省电模式。省电策略会限制后台进程，可能影响音频处理。

**再查**：是不是同时在跑很多占用资源的应用（比如游戏本身已经很吃性能）。

**说明**：本项目**不设延迟硬指标**，判断标准是连续可听。偶发一两次卡顿可以接受，持续卡顿则视为不通过。

## 症状五：云端编译失败（Actions 出现红叉）

**要做什么**：点进失败的那次运行，看报错日志的最后几十行。

常见原因与处理：

| 现象 | 大概率原因 | 处理 |
| --- | --- | --- |
| 提示找不到签名相关信息 | 加密变量没配或名字不对 | 回 [development.md](development.md) 第五节重新配置，注意变量名要和配置里一致 |
| 提示依赖下载失败 | 网络波动 | 在 Actions 页面手动重跑一次 |
| 提示某行代码语法错误 | 代码写错了 | 看日志指出的文件与行号，改掉 |

## 症状六：装不上，提示签名不一致

**原因**：新安装包和手机上已装的那个，签名不是同一个。

**处理**：卸载手机上的旧版本，再安装新的。

**说明**：这是安卓的正常限制，不是缺陷。但要注意卸载会清掉工具的设置（比如你选过的音乐软件），需要重新选一次。想要避免这种情况，就必须始终使用同一套签名，见 [development.md](development.md) 第五节。

## 症状七：换了另一台手机后不管用

**先查**：新手机上执行症状一里的第 1、2 两项，确认 root 和中转站设备都存在。

**说明**：本项目只在 realme RMX5010 / ColorOS 16 上实测过。换机后即使两个前提都满足，也可能因为音频策略差异而失效。先按症状一完整排查，把结果记录下来再决定怎么办，不要直接改代码。

## 收集信息再求助

如果排查完还是没有头绪，把这些信息收集齐，能极大加快定位：

1. 手机型号与系统版本；
2. 症状一的四项检查结果；
3. 具体症状（哪一步、期望什么、实际什么）；
4. 如果是编译问题，附上 Actions 的报错日志。
