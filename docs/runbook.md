# 出问题了先查这里

## 症状一：开关打开后，队友完全听不见歌

按顺序查这五项，哪一项不过就先解决它。

**1. root 还在不在**

- **在哪做**：Termux 终端。
- **执行什么**：`su -c id`
- **看到什么算成功**：输出里有 `uid=0(root)`。
- **不过怎么办**：检查 KernelSU 是否正常、有没有给本工具授权。

**2. 工具文件在不在**

- **执行什么**：`su -c 'ls /data/misc/audioserver/libmcpayload.so'`
- **看到什么算成功**：打印出这个路径。
- **不过怎么办**：在界面上把开关关掉再打开一次，工具会自动释放。

**3. 声音服务是不是重启过**

系统声音服务被重启后，装在上面的钩子会丢失。

- **执行什么**：`su -c 'pidof audioserver'`，连查两次，看编号是否变化。
- **处理**：编号变了就说明重启过。到界面上把开关关掉再打开一次。

**4. 音乐软件有没有选对**

界面上选中的，必须和实际在放歌的是同一个。选了 A 却在用 B 放歌，结果就是静音。

**5. 音乐是不是真的在放**

工具抄的是音乐软件交给系统的声音。歌没在放，自然没东西可送。

## 症状二：队友听见歌，但同时也听见游戏枪声或队友自己的声音（回音）

抄的范围没限定住，不止一个应用的声音被送了出去。

**先查**：界面上是不是只选中了一个音乐软件。

**还要查**：有没有别的应用在同时放声音（后台视频、系统提示音）。

**说明**：确认已指定正确的软件、也没有别的应用在放声音，却还有回音，就是实现缺陷，当 bug 处理。

## 症状三：关掉开关后，队友还是听不见我说话

**最需要重视的症状**：真实麦克风没有恢复。

**要做什么**：

1. 先重启一次手机，看是否恢复；
2. 恢复后，重开再关一次，看能不能复现；
3. 能稳定复现就别再用了，这是必须修的缺陷。

**参考**：[security.md](security.md) 第四节把「关不掉」列为真实风险。

## 症状四：歌能听见，但断断续续、卡顿

**先查**：手机是不是在低电量模式或省电模式。省电策略会限制后台进程。

**再查**：是不是同时跑了很多吃性能的应用。

**说明**：本项目不设延迟硬指标，只看连续可听。偶发一两次卡顿可以接受，持续卡顿算不通过。

## 症状五：云端编译失败（Actions 出现红叉）

**要做什么**：点进失败的那次运行，看报错日志最后几十行。

| 现象 | 处理 |
| --- | --- |
| 提示找不到签名相关信息 | 回 [development.md](development.md) 第五节重新配 |
| 提示依赖下载失败 | 在 Actions 页面手动重跑一次 |
| 提示原生编译失败 | 看日志里的文件名和行号，改 `native/` 下的源码 |
| 提示某行代码语法错误 | 看日志指出的文件和行号，改掉 |

## 症状六：装不上，提示签名不一致

新安装包和手机上已装的那个，签名不是同一个。

**处理**：卸载手机上的旧版本，再装新的。卸载会清掉工具的设置，要重新选一次音乐软件。

## 症状七：换了另一台手机后不管用

**先查**：在新手机上重做症状一的第 1、2 项。

**说明**：本项目只在 realme RMX5010 / ColorOS 16 上实测过。工具里的库内地址按本机实测值写死，换机型要重新求这两个地址，做法见 [testing.md](testing.md) 最后一节。

## 症状八：通知栏看不到那个快捷开关

**按顺序查**：

1. **通知权限是否被拒**：到系统设置里的应用通知权限，确认本工具的通知是允许的。
2. **开关是不是真开着**：通知只在开关打开时挂出，关掉后会撤走。
3. **是不是被系统收纳了**：下拉展开「静默通知」一类的分组看看。

这一项不影响主要功能：回到应用界面操作开关完全一样。

## 症状九：手机上出现刺耳的外放

工具本身不产生声音输出。发现外放时查这两处：

**1. 音量是不是 0**

- **执行什么**：`su -c 'settings --user 0 get system volume_music'`
- 不是 0 就调成 0：`su -c 'settings --user 0 put system volume_music 0'`

**2. 蓝牙耳机有没有断开**

蓝牙耳机断开的瞬间，声音会回落到扬声器。重新连上即可。

## 查完还是没头绪

把这些信息收集齐，能大大加快定位：

1. 手机型号与系统版本；
2. 症状一里前四项的检查结果；
3. 具体症状（哪一步、期望什么、实际什么）；
4. 如果是编译问题，附上 Actions 的报错日志。
