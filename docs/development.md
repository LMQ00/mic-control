# 怎么构建、怎么装到手机上

这份文档写给两类人：一类是想把代码变成手机上能装的安装包的人，一类是只想装上用、不关心代码的人。无论你是哪一种，构建这件事都不需要在你自己的电脑上装一堆开发工具——代码提交到 GitHub 以后，云端会自动帮你编译好。这份文档会告诉你提交之后去哪儿拿安装包、怎么装、以及最关键的签名问题怎么处理。读完它，你能独立完成一次"改代码 → 拿到新安装包 → 装进手机"的完整循环。

## 一、整体流程一览

```
你改代码 → 提交到 GitHub → 云端自动开始编译 → 编译完产出安装包
                                                      ↓
                                        从 GitHub 下载安装包 → 装进手机
```

你的手机只负责"装"，不负责"编"。开发机是 Termux，不装 Android 开发工具链。

## 二、第一次要做的事：建仓库

- **在哪执行**：手机上的 Termux 终端，先进入项目目录。
- **执行什么**：

```bash
git init
git add -A
git commit -m "chore: 初始化仓库"
gh repo create mic-control --public --source=. --remote=origin --push
```

- **看到什么算成功**：命令执行完没有报错，浏览器打开 `https://github.com/LMQ00/mic-control` 能看到你的代码。
- **说明**：仓库名 `mic-control`、公开可见，这是项目定下的规矩。`gh` 已经在本机登录过，直接就能用。

## 三、编译是怎么触发的

代码推到 GitHub 之后，云端会读取仓库里的工作流配置，自动开始编译。触发方式有两种：

- **自动**：每次推送到主分支，自动编译一次，产出可下载的安装包；
- **手动**：在 GitHub 网页上进入 Actions 页面，选中对应的工作流，点按钮手动跑一次。

**要做什么**：推送代码后，打开仓库的 Actions 页面，看最新一次运行。

**看到什么算成功**：运行记录前面出现绿色对勾，点进去能在页面底部找到可下载的构建产物。

**如果出现红色叉**：点进去看报错日志。常见的失败原因和处理办法见 [runbook.md](runbook.md)。

## 四、怎么把安装包装进手机

**要做什么**：

1. 在构建产物页面把安装包下载到手机；
2. 在手机上点击这个文件完成安装；
3. 首次安装时系统可能提示"来自未知来源"，允许即可。

**看到什么算成功**：手机应用列表里出现本工具，能打开，界面上有一个开关和一个音乐软件列表。

**关于覆盖安装**：正常情况下新版可以直接覆盖旧版安装，不需要卸载。如果哪天提示签名不一致，说明签名发生了变动，处理办法见下面第五节。

## 五、签名必须处理好

安卓要求每个安装包都有签名，签名相当于安装包的身份证。它有两条硬规矩：

1. **签名不一致的安装包不能互相覆盖**——你必须先卸载旧的才能装新的；
2. **签名一旦泄露，别人可以伪造你的安装包**——所以签名文件绝不能传到公开仓库里。

本项目的做法：**签名文件不放仓库，而是加密存放在 GitHub 的仓库设置里，云端编译时临时还原出来用。**

### 当前状态：已经配置好了

项目在开发过程中已经生成了一套固定签名，并配置到仓库的四个加密变量里。**你不需要再做这一步**，直接构建就能得到可覆盖安装的包。

**关于这四个变量**：它们分别保存签名文件内容、密钥库密码、密钥别名、密钥密码。变量名一旦确定就不要改，改了云端会取不到值、构建直接失败（本项目实际踩过这个坑）。

**一个重要提醒**：签名文件和密码**必须自己备份好**。项目目录之外留有一份备份。**一旦丢失，你将无法再给出能够覆盖安装的新版本**，只能让用户卸载重装（设置会丢）。

将来若要更换签名（比如怀疑泄露），做法是：生成新签名 → 更新那四个加密变量 → 让用户卸载旧版重装。

## 六、日常开发循环

- **在哪执行**：手机上的 Termux 终端，在项目目录下。
- **执行什么**：

```bash
git add -A
git commit -m "feat: 描述你做了什么"
git push
```

- **看到什么算成功**：推送没有报错，然后去仓库的 Actions 页面看到新的运行记录变绿；把新的安装包下载装上，新功能可用。
- **约定**：每完成一个功能提交一次，提交信息用中文，加上 `feat` / `fix` / `chore` 前缀，让人一眼能看出这次是加功能、修问题还是杂事。

## 七、本地不编译

- 开发机是 Termux，不是常规电脑，装 Android 开发工具链体积大、也容易出兼容问题；
- 云端构建的环境是干净且可复现的，同样的代码在哪里跑结果都一样；
- 你只需要能下载安装包来验证，不需要在本地产出安装包。

因此，如果有人在项目里发现本地构建的痕迹（比如本地的开发工具配置、编译产物目录），那属于偏离约定，应当清理掉。
