# 怎么构建、怎么装到手机上

## 一、整体流程

```
你改代码 → 推到 GitHub → 云端自动编译 → 产出安装包
                                          ↓
                            从 GitHub 下载安装包 → 装进手机
```

你的手机只负责装，不负责编。开发机是 Termux，不装 Android 开发工具链。

## 二、第一次要做的事：建仓库

**在哪做**：手机上的 Termux 终端，先进入项目目录。

**执行什么**：

```bash
git init
git add -A
git commit -m "chore: 初始化仓库"
gh repo create mic-control --public --source=. --remote=origin --push
```

**看到什么算成功**：命令没报错，浏览器打开 `https://github.com/LMQ00/mic-control` 能看到代码。

**说明**：仓库名 `mic-control`、公开可见，这是项目定下的规矩。`gh` 本机已经登录过，直接能用。

## 三、怎么触发编译

代码推到 GitHub 之后，云端读仓库里的配置自动开始编译。两种触发方式：

- **自动**：每次推到主分支都会编译一次，产出可下载的安装包；
- **手动**：在 GitHub 网页进 Actions 页面，选中工作流，点按钮跑一次。

**要做什么**：推送后打开仓库的 Actions 页面，看最新一次运行。

**看到什么算成功**：运行记录前面是绿色对勾，点进去能在页面底部找到可下载的安装包。

**如果是红色叉**：点进去看报错日志，常见问题见 [runbook.md](runbook.md)。

## 四、怎么装进手机

**要做什么**：

1. 在构建产物页面把安装包下载到手机；
2. 在手机上点这个文件完成安装；
3. 首次安装系统可能提示"来自未知来源"，允许即可。

**看到什么算成功**：应用列表里出现本工具，能打开，界面上有一个开关和一个音乐软件列表。

**覆盖安装**：正常情况下新版直接覆盖旧版，不用卸载。如果提示签名不一致，处理办法见第五节。

## 五、签名

安卓要求每个安装包都有签名，签名相当于安装包的身份证。两条硬规矩：

1. **签名不一样的安装包不能互相覆盖**，必须先卸载旧的才能装新的；
2. **签名泄露了，别人可以伪造你的安装包**。签名文件绝不能传到公开仓库。

本项目的做法：**签名文件不进仓库，加密存在 GitHub 的仓库设置里，云端编译时临时取出来用。**

### 已经配好了

项目已经生成了一套固定签名，配到仓库的四个加密变量里。**这一步你不需要再做**，直接构建就能得到可覆盖安装的包。

**四个变量**分别存签名文件内容、密钥库密码、密钥别名、密钥密码。变量名确定后不要改，改了云端取不到值、构建直接失败。

**要紧的一条**：签名文件和密码**必须自己备份好**。项目目录之外留了一份。**一旦丢失，就再也给不出能覆盖安装的新版本**，只能让用户卸载重装（设置会丢）。

将来要换签名（比如怀疑泄露）：生成新签名 → 更新那四个加密变量 → 让用户卸载旧版重装。

## 六、日常开发

**在哪做**：手机上的 Termux 终端，在项目目录下。

**执行什么**：

```bash
git add -A
git commit -m "feat: 描述你做了什么"
git push
```

**看到什么算成功**：推送没报错，Actions 页面新的运行记录变绿；下载新包装上，新功能可用。

**约定**：每完成一个功能提交一次，提交信息用中文，加 `feat` / `fix` / `chore` 前缀，一眼能看出这次是加功能、修问题还是杂事。

## 七、本地不编译

开发机是 Termux，不装 Android 开发工具链。编译全部在云端完成，环境干净且每次一致。

项目里不保留本地构建的痕迹（本地开发工具配置、编译产物目录等）；出现了就清理掉。
