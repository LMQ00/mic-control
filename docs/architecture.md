# 声音怎么走：这个工具的原理

想象一下你戴着耳机在打游戏，队友能听见你说话，是因为游戏向手机要麦克风的声音。这个工具做的事，就是在你按下开关以后，把游戏要麦克风的那只手，悄悄牵到音乐播放器上——于是队友听见的是你放的歌，而不是你房间里的动静。这份文档就是把这个过程一步步讲清楚，不讲代码，只讲声音从哪来、中间经过了谁、最后到了哪里。读完它，你能明白这个软件为什么需要 root 权限，也能明白为什么必须先指定是哪个音乐软件。

## 一、手机里的声音是怎么分类的

手机内部有两股互不相干的声音通道：

- **播放通道（输出）**：音乐软件、游戏、系统提示音，都是往这条通道上送声音，最后到你的耳机或扬声器。
- **录音通道（输入）**：麦克风采集到的声音，App 通过这条通道读取，比如语音通话、录音机。

正常情况下两条通道没有任何交集：你在耳机里听到的歌，麦克风是听不见的。这个工具要做的，就是**人为地把播放通道上某一路声音，接到录音通道的入口去**。

## 二、系统给的那条"捷径"：Remote Submix

安卓系统自带一个叫 Remote Submix 的虚拟设备（中文可以理解成"远程混音"）。它不是真实硬件，而是一个中转站：

- 往它的**输出端**写入声音，等于"假装有一个 App 在播放这段声音"；
- 从它的**输入端**读声音，等于"假装有一个麦克风在采集这段声音"；
- 关键在于：写入输出端的内容，会直接出现在输入端。这就是那条捷径。

它本来是为录屏、投屏这类需求准备的——录屏时要把系统声音录进去，靠的就是它。

你手机上确实有这个设备，这一点我实际检查过，不是推测。见 [tech-stack.md](tech-stack.md) 里的环境记录。

## 三、完整的声音路径

开关打开后，声音这样走：

1. **音乐软件正常播放**。它照旧把声音送到播放通道，所以你戴着耳机照常能听见歌，这一路完全没有被改动。
2. **同时复制一份**。工具在播放通道上，只截取你指定的那一个音乐软件的声音，复制一份出来。
3. **写进中转站**。这份复制出来的声音被写入 Remote Submix 的输出端。
4. **系统按开关设置，把录音请求指向中转站**。游戏向系统要麦克风时，系统把它的录音请求路由到 Remote Submix 的输入端，而不是真实麦克风。
5. **游戏读到的是歌**。游戏拿到的数据和它平时拿到的麦克风数据格式一样，它分辨不出来，直接编码发给队友。

于是：**你的耳机里有歌，队友的耳朵里也有歌，而真实麦克风的声音没有任何人去读。**

## 四、为什么必须指定是哪个音乐软件

如果在第 2 步里不限定来源，而是把"整台手机正在播放的所有声音"都复制一份，那么连同游戏的枪声、脚步、系统提示音，全都会一起被送进麦克风。队友那边就会出现这样的效果：他听见你放的歌，同时也听见他自己刚才说的话、听见游戏里的枪声——这就是你最开始担心的**回音**。

所以界面里必须让你选中一个音乐软件，工具只截取它的声音。这不是可选项，是功能成立的前提。

## 五、开关关闭时会发生什么

关闭开关时，工具做两件事：

1. 把录音请求的路由取消，系统重新把游戏的录音指向真实麦克风；
2. 停止复制音乐声音。

这两步都是立即生效的运行期操作，**不需要重启手机，也不需要重启游戏**。关掉以后，你说话队友就能正常听见。

## 六、为什么这件事需要 root

普通 App 出于隐私保护，是不允许随便接管别人录音的。系统提供的正规途径（向用户弹窗申请"捕获其他 App 的声音"）有两个限制：

- 只能捕获那些**主动声明允许被捕获**的 App，国内部分音乐软件会明确关闭这个许可；
- 只能在自己的进程范围内使用，无法替换掉系统麦克风入口。

要绕过这两条，就必须在系统层面操作音频路由，这需要 root 权限。相关的风险与权限用途单独写在 [security.md](security.md)。

## 七、专业名词对照

| 文档里出现的词 | 说白了就是 |
| --- | --- |
| 播放通道 / 输出 | 手机往外放声音的那条路 |
| 录音通道 / 输入 | App 从麦克风读声音的那条路 |
| Remote Submix | 系统自带的虚拟中转站，写进去什么，读出来就是什么 |
| 路由 | 系统决定"这次录音请求该接到哪个设备上" |
| 音频策略 | 系统启动时读的一份配置文件，规定了有哪些设备、能怎么连 |
| 捕获 | 把某个 App 正在播放的声音复制一份出来 |

## 八、当前状态

截至本次更新，已经确认的事实（都是实机验证，不是推测）：

- 你手机上确实存在上文说的那个中转设备（Remote Submix）；
- 目标应用（以王者荣耀和系统录音机为样本）确实使用 Java 层的录音接口读取麦克风，这意味着"在录音读取处替换数据"这个做法有真实的作用对象；
- 项目已经能编译出安装包、并成功装到手机上。

**但要说清楚当前做到哪一步**：现在代码送进麦克风的还**不是真实的音乐**，而是一段用于调试的固定测试音。先送测试音是有意为之——它能用最简单的方式回答"这条链路到底通不通"这个根本问题。等链路确认打通，再把测试音换成从指定音乐软件捕获的真实声音。

还差最后一步：**模块需要手机重启一次才会被框架正式加载**。这是框架的既定机制——模块清单在开机时扫描一次，之后新装的模块要等下次重启才生效。这一步做完，就能跑 [testing.md](testing.md) 里那套验证了。

另外记录一个实现细节上的限制：录音类应用如果用的是 `MediaRecorder` 这类接口，它的声音数据不经过 Java 层，因此当前做法覆盖不到它。王者荣耀这类游戏用的是 `AudioRecord`，在覆盖范围内。这一点会影响后续要不要额外处理 `MediaRecorder`，详见 [runbook.md](runbook.md)。
