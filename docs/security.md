# root 权限用在哪、会不会偷听、有什么风险

这份文档说明这个工具使用了哪些权限、能看到什么、不会做什么。如果把工具装在别人手机上，或者你自己在意隐私，请读完这一页再做决定。读完你能知道它会不会偷偷录你说话。

## 一、它必须用 root 做什么

只有一件事：**在应用之间插手声音**。

具体说分两头：一头是在你选定的音乐软件里，复制一份它正在播放的声音；另一头是在目标应用读麦克风时，把复制来的音乐交给它。这两件事都发生在别的应用内部，普通应用没有权限碰，必须借助 root 才能做到。

除此之外它不做别的事。它不修改系统文件，不常驻后台偷偷运行，不读取你的短信、通讯录、照片、位置。

## 二、它能看到什么

**它站在声音通路上，所以它天然"路过"两样东西**：

1. **你指定的那个音乐软件正在播放的声音**——这是它的工作素材，必须经过它；
2. **目标应用所读取的麦克风数据**——它决定把这个位置换成什么。

请注意第二点意味着什么：**在开关打开期间，目标应用读麦克风时拿到的是音乐，不是你说话的声音。** 这不是它"偷听"了你的说话，恰恰相反，真实麦克风的数据没有被送去任何地方。

## 三、它绝对不会做什么

- 不会把音频数据上传到任何服务器；
- 不会在你关掉开关后继续占用麦克风或音频通路；
- 不会记录、保存你的通话或录音内容；
- 不会向系统之外的人暴露你的麦克风数据。

如果你在代码里看到任何"把音频写进文件"或"发起网络请求"的行为，那是严重偏离设计的，应当当作安全问题处理。

## 四、风险如实说

这个工具不是没有风险，以下是真实存在的：

| 风险 | 说明 | 应对 |
| --- | --- | --- |
| 权限过大 | 拿到了 root，理论上能做很多事 | 代码公开在 GitHub 上，谁都可以审；不要用来路不明的改装版 |
| 录音被替换 | 在作用范围内、且开关打开时，被勾选的应用读麦克风会拿到音乐而不是真实声音 | 用完记得关；别开着开关去打电话 |
| 关不掉 | 如果开关失效，可能恢复不了真实麦克风 | 交付前必须测"关掉后能否立即恢复"，见 [testing.md](testing.md) 第四步 |
| 与系统冲突 | 插手应用的声音可能和系统其他音频功能（比如通话降噪）相互影响 | 出问题时先关掉开关再排查，见 [runbook.md](runbook.md) |
| 升级失效 | 系统或应用升级后内部接口可能变化，工具可能失效 | 升级后重新跑一遍 [testing.md](testing.md) |

## 五、它的作用范围到底有多大

这一点容易误会，所以说清楚：**它只作用于你在模块作用范围里勾选的那些应用，不是整机全局。**

也就是说，只有被勾选的应用（比如你勾了音乐软件和游戏）在开关打开时才会被替换；没勾的应用，麦克风照常是真实麦克风。

另外，工具在开关关闭时不做任何替换——这一点在每一次录音发生时都会重新确认，所以关掉就立刻恢复。

**即便作用有范围，用完关掉开关仍然是个好习惯**，免得你忘了它还开着，然后在被勾选的应用里说话却没人听见。

## 六、密钥与凭据

- 安装包的签名密钥**不会出现在公开仓库里**，它加密存放在构建平台的变量里；
- 你自己的手机 root 权限、GitHub 账号凭据，都不需要交给这个工具；
- 本项目不会向你索取任何账号密码。
