# root 权限用在哪、会不会偷听、有什么风险

## 一、root 用来做什么

只有一件事：**在应用之间插手声音**。

分两头：一头是在你选定的音乐软件里，抄一份它正在放的声音；另一头是在目标应用读麦克风时，把抄来的音乐交给它。这两件事都发生在别的应用内部，普通应用没权限碰，必须靠 root。

除此之外它不做别的：不改系统文件，不常驻后台偷偷跑，不读你的短信、通讯录、照片、位置。

## 二、它能看到什么

**它站在声音通路上，会路过两样东西**：

1. **你指定的那个音乐软件正在放的声音**——这是它的原料，必须经过它；
2. **目标应用读到的麦克风数据**——它决定把这里换成什么。

第二点：**开关打开期间，目标应用读麦克风时拿到的是音乐，不是你说话的声音。** 真实麦克风的数据没有被送到任何地方去。

## 三、它不会做什么

- 不会把声音数据传到任何服务器；
- 不会在你关掉开关后继续占用麦克风或声音通路；
- 不会记录、保存你的通话或录音内容；
- 不会把你的麦克风数据给系统以外的任何人。

如果在代码里看到"把声音写进文件"或"发起网络请求"的行为，那是严重偏离设计的，应当当安全问题处理。

## 四、真实存在的风险

| 风险 | 说明 | 应对 |
| --- | --- | --- |
| 权限太大 | 拿到了 root，理论上能做很多事 | 代码公开在 GitHub 上，谁都能审；不要用来路不明的改装版 |
| 录音被换掉 | 在范围内、开关打开时，勾选的应用读麦克风会拿到音乐而不是真实声音 | 用完记得关；别开着开关去打电话 |
| 关不掉 | 万一开关失效，可能恢复不了真实麦克风 | 交付前必须测"关掉后能否立即恢复"，见 [testing.md](testing.md) 第四步 |
| 与系统冲突 | 插手应用的声音，可能和系统其他音频功能（比如通话降噪）互相影响 | 出问题先关掉开关再排查，见 [runbook.md](runbook.md) |
| 升级后失效 | 系统或应用升级后内部接口可能变，工具可能失效 | 升级后重跑一遍 [testing.md](testing.md) |

## 五、作用范围有多大

**它只作用于你在模块作用范围里勾选的那些应用，不是整台手机。**

只有勾了的应用（比如你勾了音乐软件和游戏）在开关打开时才会被换掉；没勾的应用，麦克风照常是真的。

关掉开关时不做任何替换。这一点在每次录音发生时都会重新确认，关掉就立刻恢复。

**就算有范围限制，用完关掉开关仍然是个好习惯**，免得你忘了它还开着，然后在勾选的应用里说话却没人听见。

## 六、密钥与凭据

- 安装包的签名密钥**不在公开仓库里**，加密存放在构建平台的变量里；
- 你的手机 root 权限、GitHub 账号凭据，都不需要交给这个工具；
- 本项目不会向你索取任何账号密码。
