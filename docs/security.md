# root 权限用在哪、会不会偷听、有什么风险

这个工具要动用手机的 root 权限，这听起来就让人警惕，所以这份文档把话说明白：它到底拿了什么权限、为什么非拿不可、它能看到什么、又绝对不会做什么。如果你是把这个工具装在别人手机上，或者你自己在意隐私，请读完这一页再做决定。读完它，你应该能回答"它会不会偷偷录我说话"这个问题。

## 一、它必须用 root 做什么

只有一件事：**改音频路由**。

具体说，就是让系统把"游戏要麦克风"这个请求，转接到那个虚拟中转站上去。这个操作由系统底层管理，普通应用没有权限碰，必须 root。

除此之外它不做别的事。它不修改系统文件，不常驻后台偷偷运行，不读取你的短信、通讯录、照片、位置。

## 二、它能看到什么

**它是音频通路的中间人，所以它天然"路过"两样东西**：

1. **你指定的那个音乐软件正在播放的声音**——这是它的工作素材，必须经过它；
2. **使用麦克风的 App 所请求的音频数据**——它决定把这些请求转给谁。

请注意第二点意味着什么：**在开关打开期间，如果某个 App 在录音，那么这个 App 拿到的数据实际是音乐，不是你的说话声。** 这不是它"偷听"了你的说话，恰恰相反，是真实麦克风根本没被读取。

## 三、它绝对不会做什么

- 不会把音频数据上传到任何服务器；
- 不会在你关掉开关后继续占用麦克风或音频通路；
- 不会记录、保存你的通话或录音内容；
- 不会向系统之外的人暴露你的麦克风数据。

如果你在代码里看到任何"把音频写进文件"或"发起网络请求"的行为，那是严重偏离设计的，应当当作安全问题处理。

## 四、风险如实说

这个工具不是没有风险，以下是真实存在的：

| 风险 | 说明 | 应对 |
| --- | --- | --- |
| 权限过大 | 拿到了 root，理论上能做很多事 | 代码公开在 GitHub 上，谁都可以审；不要用来路不明的改装版 |
| 录音异常 | 开关打开时，所有用麦克风的 App 都会拿到音乐而不是真实声音 | 用完记得关；测试时别开着开关去打电话 |
| 关不掉 | 如果开关失效，可能恢复不了真实麦克风 | 交付前必须测"关掉后能否立即恢复"，见 [testing.md](testing.md) 第四步 |
| 与系统冲突 | 改音频路由可能和系统其他音频功能（比如通话降噪）打架 | 出问题时先关掉开关再排查，见 [runbook.md](runbook.md) |
| 升级失效 | 系统升级后音频策略可能变化，工具可能失效 | 升级系统后重新跑一遍 [testing.md](testing.md) |

## 五、你在授权前应该知道的一件事

**当你把开关打开，你等于告诉手机："从现在起，任何 App 要麦克风，我给它的都是音乐。"**

这是你想要的整活效果，但它也确实意味着：这段时间里，如果有 App 想录你说话，它录不到真实声音。这是一个**全局性**的开关，不是只针对游戏。所以用完之后关掉它，是使用习惯的一部分。

## 六、密钥与凭据

- 安装包的签名密钥**不会出现在公开仓库里**，它加密存放在构建平台的变量里；
- 你自己的手机 root 权限、GitHub 账号凭据，都不需要交给这个工具；
- 本项目不会向你索取任何账号密码。
