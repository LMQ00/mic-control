# root 权限用在哪、会不会偷听、有什么风险

## 一、root 用来做什么

只有一件事：**在声音服务的两个关口上装钩子**。

装的时候要把一个库加载进系统声音进程，这必须有 root。装完之后，抄音乐和换麦克风数据都在那个进程里完成。

除此之外它不做别的：不改系统文件，不常驻后台偷偷跑，不读你的短信、通讯录、照片、位置。

## 二、它能看到什么

它站在声音通路上，会路过两样东西：

1. **你选定的那个音乐软件正在放的声音**——这是原料，必须经过它；
2. **目标应用读到的麦克风数据**——它决定把这里换成什么。

另外，声音服务经手的其他应用的声音也会被它扫到一眼，但它**只按应用编号挑出你选中的那一路**，其余不读取、不保存。

## 三、它不会做什么

- 不会把声音数据传到任何服务器；
- 不会在你关掉开关后继续占用麦克风或声音通路；
- 不会记录、保存你的通话或录音内容；
- 不会把你的麦克风数据给系统以外的任何人。

如果在代码里看到「把声音写进文件」或「发起网络请求」的行为，那是严重偏离设计的，应当当安全问题处理。

## 四、真实存在的风险

| 风险 | 说明 | 应对 |
| --- | --- | --- |
| 权限太大 | 拿到了 root，理论上能做很多事 | 代码公开在 GitHub 上，谁都能审；不要用来路不明的改装版 |
| 录音被换掉 | 开关打开期间，所有应用读麦克风拿到的都是音乐而不是真实声音 | 用完记得关；别开着开关去打电话 |
| 关不掉 | 万一开关失效，可能恢复不了真实麦克风 | 交付前必须测「关掉后能否立即恢复」，见 [testing.md](testing.md) 第五步 |
| 声音服务被重启 | 钩子会丢失，工具静默失效 | 到界面上把开关关掉再打开 |
| 升级后失效 | 系统升级后库内地址可能变，工具可能失效 | 升级后重跑一遍 [testing.md](testing.md) |

## 五、作用范围有多大

**它作用于整台手机的声音服务，不限于某几个应用。**

开关打开期间，任何应用读麦克风拿到的都会是音乐。要让它在关闭时立刻恢复，见第四步的验证要求。

**用完关掉开关是个好习惯**，免得你忘了它还开着，然后接电话却没人听见。

## 六、密钥与凭据

- 安装包的签名密钥**不在公开仓库里**，加密存放在构建平台的变量里；
- 你的手机 root 权限、GitHub 账号凭据，都不需要交给这个工具；
- 本项目不会向你索取任何账号密码。
