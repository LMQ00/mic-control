# 用了什么技术、跑在什么环境上

## 一、目标手机

| 项目 | 实际情况 |
| --- | --- |
| 手机型号 | realme RMX5010 |
| 系统 | ColorOS 16 |
| Android 版本 | Android 16 |
| root 方案 | KernelSU，`su` 提权可用 |
| 系统收发声音的程序 | 主叫 `audioserver`，root 可注入 |
| 系统库 | `libaudioflinger.so`、`libaudiohal@aidl.so` |

不需要装任何框架模块。

## 二、两个关口的位置

| 关口 | 所在库 | 库内地址 | 函数 |
| --- | --- | --- | --- |
| 出口（应用放的声音汇总） | `libaudioflinger.so` | `0x1a4c14` | `Track::getNextBuffer` |
| 入口（应用读麦克风） | `libaudiohal@aidl.so` | `0x168b30` | `StreamInHalAidl::read` |

这两个地址是本机实测值。换机型要重新测。

## 三、声音格式

| 环节 | 格式 |
| --- | --- |
| 出口抄到的 | 16 位整数，采样率跟随音轨，立体声 |
| 工具内部缓冲区 | 16 位整数，采样率跟随采集到的音轨，立体声 |
| 入口写回 | 16 位整数，采样率与声道数跟随该录音流 |

## 四、录音流的采样率与声道数

系统里同时有 16000 和 48000 的录音流，都会经过同一个入口函数。

入口钩子从录音流对象里读这两个值：

| 字段 | 对象内偏移 |
| --- | --- |
| 采样率 | `0x44` |
| 声道掩码 | `0x48` |

声道数按掩码里有几位算：`0xC` 两位，是立体声；`0x10` 一位，是单声道。

每输出一帧要从环形缓冲吃掉多少帧：`缓冲写入速率 ÷ 该流采样率`，按 16 位小数保存。环形缓冲的写入速率每秒实测一次，连续三次得到同一个标准值才切换。

## 五、用了哪些技术

| 层面 | 选择 |
| --- | --- |
| 手机界面 | Kotlin + Jetpack Compose |
| 装钩子 | 自带的 `mcinject`，用 ptrace 把载荷加载进声音服务 |

| 构建 | GitHub Actions 云端构建 |
| 签名 | 固定密钥，存 GitHub 加密变量 |

## 六、钩子的写法

系统库带指针校验。把函数地址直接换成自己的会被拦下并崩溃，这一条实测过。

采用的写法是写跳转指令：

- 出口：`bti jc` + `ldr x16` + `br x16` + 处理器地址，占 20 字节；
- 入口：保留首条 `bti c`，从 `+4` 起写 `ldr x16` + `br x16` + 处理器地址，占 16 字节。

系统库的代码段开了分支落点校验（BTI），跳转只能落到 `bti` 指令上。原函数中段没有 `bti`。覆盖区末尾补一条 `bti c` 作为落点，被它占掉的那条原指令改到载荷里的影子入口重放。

影子入口依次做三件事：执行原函数开头被覆盖的几条指令、补齐落点上那条指令、跳回落点。跳回用 `bti c` + `ldr x16, #8` + `br x16` + 落点地址。

处理器进影子入口前不需要改入口字节，入口只在装和卸的时候各写一次。两处各用一把自旋锁串行化。
