# 用了什么技术、跑在什么环境上

## 一、目标手机

| 项目 | 实际情况 |
| --- | --- |
| 手机型号 | realme RMX5010 |
| 系统 | ColorOS 16 |
| Android 版本 | Android 16 |
| root 方案 | KernelSU（一种给手机加 root 的工具），`su` 提权可用 |
| 框架 | LSPosed（让模块能插手其他应用的工具）**已装好**，它需要的 Zygisk 也配好了 |
| 系统收发声音的程序 | **够不着，不在范围内**，只能在各个应用里分别处理 |

LSPosed 和它的依赖都不用你再装，直接装本项目的模块就能用。

## 二、目标应用用的接口（实测）

工具要生效，前提是目标应用的声音走的是工具能插手的那几种接口。

| 应用 | 放声音用的接口 | 读麦克风用的接口 | 管不管得了 |
| --- | --- | --- | --- |
| 网易云音乐（放歌的） | Java 层播放接口 | —— | 管得了 |
| 王者荣耀（语音的） | —— | Java 层录音接口 | 管得了 |
| 系统录音机 | —— | `MediaRecorder` | 管不了 |

`MediaRecorder` 是另一套录音接口，它的数据不经过工具能插手的那一层。这是已知限制，不是配置问题。

## 三、声音格式

沿用系统音频设备本来的格式：**16 位、48000 赫兹、立体声**。工具内部不转换、不改参数，抄到什么就原样送什么。

## 四、两个影响手感的取值

| 项目 | 取值 | 说明 |
| --- | --- | --- |
| 开关生效延迟 | 最多四分之一秒 | 确认设置有没有改动这件事开销不小，而录音读取每十来毫秒一次。每次都去确认会把开销压进声音通路、造成卡顿。现在是每 250 毫秒确认一次，你感觉不到这点延迟 |
| 没声音时是否等一等 | 不等 | 开关开着但还没放歌时，如果每次都等，会把游戏语音拖卡。现在只有确认对面正在出声才稍等一下，其余情况立刻返回，让麦克风保持原样 |

## 五、用了哪些技术

| 层面 | 选择 | 说明 |
| --- | --- | --- |
| 手机界面 | Kotlin + Jetpack Compose | 界面只有开关和一个列表，用不到复杂框架 |
| 系统侧模块 | LSPosed 模块 | 手机上已经装好，用户不用额外准备 |
| 提权 | KernelSU 的 `su` | 这台手机现有的 root 能力，实测可用 |
| 抄音乐 | 拦下音乐应用的播放写入 | 只抄指定的那一个应用，正好满足"指定音乐软件"的要求 |
| 跨应用传声 | 手机内部私有管道 | 两个应用是隔离的进程，不能直接共享内存，要有条通道 |
| 换录音 | 拦下目标应用的录音读取 | 不管上层用哪个语音组件，Java 层录音最后都会走到这里 |
| 构建 | GitHub Actions 云端构建 | 开发机是 Termux，没有 Android SDK，也不打算装 |
| 签名 | 固定密钥，存 GitHub 加密变量 | 签名不一致就装不上、必须先卸载，固定下来就没这个麻烦 |

## 六、开发机

| 项目 | 实际情况 |
| --- | --- |
| 环境 | Termux（手机上的 Linux 终端） |
| git | 2.55 |
| GitHub CLI | 2.97，已登录 LMQ00，能建仓库、能跑 Actions |
| Java | OpenJDK 21（只用来生成签名密钥，不编译应用） |
| Android SDK / Gradle | **本地没有，也不打算装** |

本地没有构建工具链，**所有编译都在 GitHub Actions 上完成**，装到手机上的包由云端产出后下载。流程见 [development.md](development.md)。

## 七、适用范围

- 目前**只在上面那台 realme 手机上实测过**。
- 代码里没有写死机型或系统版本，理论上换手机也能试。换机后要排查，重点是确认目标应用用的是哪类接口（见第二节）。
- 换了手机发现不管用，别急着改代码，先按 [runbook.md](runbook.md) 排查。
