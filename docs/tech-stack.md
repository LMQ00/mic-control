# 用了什么技术、跑在什么环境上

这份文档记录两件事：做这个工具用到了哪些技术，以及它是在一台什么样的手机上开发和验证的。之所以要专门记下来，是因为这类涉及系统底层的工具对手机型号和系统版本很敏感——同样一段代码，换台手机可能就完全不管用。你在别的手机上遇到问题时，先回来对照这里的环境记录，看看差异在哪。读完它，你能知道这套东西的"适用范围"边界在哪里。

## 一、目标环境（实机检查结果，非推测）

| 项目 | 实际情况 |
| --- | --- |
| 手机品牌 / 型号 | realme RMX5010 |
| 系统 | ColorOS 16 |
| Android 版本 | Android 16（API 36） |
| root 方案 | KernelSU，已验证 `su` 提权可用 |
| Hook 框架 | LSPosed **已安装**，且已配套装好 Zygisk 支持 |

**这意味着：** 你不需要再额外安装 LSPosed 或其依赖，直接装本项目的模块就能用。

## 二、音频环境（实机检查结果）

系统启动时会读取一份音频策略配置，其中明确引入了 Remote Submix 模块，具体能力如下：

| 项目 | 实际情况 |
| --- | --- |
| 支持的采样率 | 48000 Hz |
| 支持的格式 | PCM 16 位 |
| 支持的声道 | 立体声 |
| 提供的能力 | 一个虚拟输出端（写声音进去）、一个虚拟输入端（读声音出来） |

这套参数就是本项目的默认音频规格：**直接采用系统给的能力，不做重采样，不改参数**。这样最不容易出问题。

## 三、技术选型

| 层面 | 选择 | 为什么这么选 |
| --- | --- | --- |
| 手机界面 | Kotlin + Jetpack Compose | 界面只有开关和音乐软件列表，用不到复杂框架；Compose 写起来快，界面状态和开关状态天然同步 |
| 系统侧模块 | LSPosed 模块 | 手机上已装好，无需用户额外准备；能在系统层面介入音频路由 |
| 提权方式 | KernelSU 的 `su` | 已实测可用，是这台手机现有的 root 能力 |
| 声音中转 | 系统自带 Remote Submix 设备 | 系统原生提供，不需要额外写驱动；能同时满足"整机生效"和"不用针对具体游戏适配" |
| 构建 | GitHub Actions 云端构建 | 开发机是 Termux，没有 Android SDK；把构建放云端可以避免在手机上装几个 G 的工具链 |

## 四、开发机环境

| 项目 | 实际情况 |
| --- | --- |
| 环境 | Termux（手机上的 Linux 终端） |
| git | 2.55 |
| GitHub CLI | 2.97，已登录账号 LMQ00，具备创建仓库和跑 Actions 的权限 |
| Android SDK / Gradle | **本地没有，也不打算装** |

因为本地没有构建工具链，**所有编译都在 GitHub Actions 上完成**，装到手机上的安装包由云端构建产出后下载。具体流程见 [development.md](development.md)。

## 五、适用范围说明

- 当前**只在上面那台 realme 手机上实际验证过**。
- 设计上不把机型和系统版本写死在代码里，所以理论上换手机也能试，但换机后大概率需要重新确认两件事：这台手机有没有 Remote Submix 设备、音频路由能不能被改动。
- 如果你换了手机发现不管用，别急着改代码，先按 [runbook.md](runbook.md) 做排查，很可能只是环境差异。
