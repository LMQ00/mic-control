# 用了什么技术、跑在什么环境上

这份文档记录两件事：做这个工具用到了哪些技术，以及它是在一台什么样的手机上开发和验证的。这类涉及系统底层的工具对手机型号和系统版本较敏感，换台手机可能就不管用。在别的手机上遇到问题时，先回来对照这里的环境记录。读完你能知道这套东西的适用范围边界。

## 一、目标环境（实机检查结果，非推测）

| 项目 | 实际情况 |
| --- | --- |
| 手机品牌 / 型号 | realme RMX5010 |
| 系统 | ColorOS 16 |
| Android 版本 | Android 16（API 36） |
| root 方案 | KernelSU，已验证 `su` 提权可用 |
| Hook 框架 | LSPosed **已安装**，且已配套装好 Zygisk 支持 |
| 系统收发声音的程序 | **不在覆盖范围内**，工具无法从它入手，只能在各个应用里分别处理 |

**这意味着：** 你不需要再额外安装 LSPosed 或其依赖，直接装本项目的模块就能用。

## 二、目标应用的接口情况（实测）

工具要生效，前提是目标应用的声音走的是工具能插手的那几种接口。实测结果：

| 应用 | 播放声音用的接口 | 读麦克风用的接口 | 是否在覆盖范围 |
| --- | --- | --- | --- |
| 网易云音乐（音乐来源） | Java 层播放接口 | —— | 是 |
| 王者荣耀（语音端） | —— | Java 层录音接口 | 是 |
| 系统录音机 | —— | `MediaRecorder` | 否，见下方说明 |

**说明**：`MediaRecorder` 的声音数据不经过工具能插手的那一层，因此用它的应用覆盖不到。这是已知限制，不是配置问题。

## 三、音频规格

沿用系统音频设备的原生能力：**PCM 16 位 / 48000 Hz / 立体声**。工具内部不做重采样、不改参数，直接把截到的数据原样传递，这样最不容易出问题。

## 四、两个影响使用感受的取值

这两项是刻意选的，直接决定"用起来跟不跟手"：

| 项目 | 取值 | 说明 |
| --- | --- | --- |
| 开关生效延迟 | 最多四分之一秒 | 确认设置有没有改动这件事开销不小，而录音读取每十来毫秒一次；若每次都去确认，开销会压进音频路径、造成卡顿。现改成每 250 毫秒确认一次——你感觉不到这点延迟，音频路径却轻松很多 |
| 没有声音时是否等待 | 不等待 | 开关开着但还没开始放歌时，若每次都等，会把游戏语音拖卡。现在只有确认对面正在出声才稍作等待，其余情况立刻返回，让麦克风保持原样 |

## 五、技术选型

| 层面 | 选择 | 说明 |
| --- | --- | --- |
| 手机界面 | Kotlin + Jetpack Compose | 界面只有开关和音乐软件列表，用不到复杂框架；Compose 写起来快，界面状态和开关状态天然同步 |
| 系统侧模块 | LSPosed 模块 | 手机上已装好，无需用户额外准备；能在系统层面介入应用的声音 |
| 提权方式 | KernelSU 的 `su` | 已实测可用，是这台手机现有的 root 能力 |
| 声音截取 | 拦截音乐应用的播放写入 | 只截指定的那一个应用，天然满足"指定音乐软件"的要求 |
| 跨应用传声 | 手机内部私有管道 | 两个应用是隔离的进程，不能直接共享内存，需要一条通道 |
| 录音替换 | 拦截目标应用的录音读取 | 无论上层用哪个语音 SDK，Java 层录音最终都会走到这里 |
| 构建 | GitHub Actions 云端构建 | 开发机是 Termux，没有 Android SDK；把构建放云端可以避免在手机上装几个 G 的工具链 |
| 签名 | 固定密钥，存 GitHub 加密变量 | 签名不一致会导致新包无法覆盖安装、必须卸载重装；固定下来就没有这个麻烦 |

## 六、开发机环境

| 项目 | 实际情况 |
| --- | --- |
| 环境 | Termux（手机上的 Linux 终端） |
| git | 2.55 |
| GitHub CLI | 2.97，已登录账号 LMQ00，具备创建仓库和跑 Actions 的权限 |
| Java | OpenJDK 21（仅用于生成签名密钥等辅助操作，不用于编译应用） |
| Android SDK / Gradle | **本地没有，也不打算装** |

本地没有构建工具链，**所有编译都在 GitHub Actions 上完成**，装到手机上的安装包由云端构建产出后下载。具体流程见 [development.md](development.md)。

## 七、适用范围说明

- 当前**只在上面那台 realme 手机上实际验证过**。
- 设计上不把机型和系统版本写死在代码里，所以理论上换手机也能试。换机后如果要排查，重点是确认目标应用用的是哪类接口（见第二节）。
- 如果你换了手机发现不管用，别急着改代码，先按 [runbook.md](runbook.md) 做排查，很可能只是目标应用的接口不在覆盖范围。
