# 用了什么技术、跑在什么环境上

## 一、目标手机

| 项目 | 实际情况 |
| --- | --- |
| 手机型号 | realme RMX5010 |
| 系统 | ColorOS 16 |
| Android 版本 | Android 16 |
| root 方案 | KernelSU，`su` 提权可用 |
| 系统收发声音的程序 | 主叫 `audioserver`，root 可注入 |
| 系统库 | `libaudioflinger.so`、`libaudiohal@aidl.so` |

不需要装任何框架模块。

## 二、两个关口的位置

| 关口 | 所在库 | 库内地址 | 函数 |
| --- | --- | --- | --- |
| 出口（应用放的声音汇总） | `libaudioflinger.so` | `0x1a4c14` | `Track::getNextBuffer` |
| 入口（应用读麦克风） | `libaudiohal@aidl.so` | `0x168b30` | `StreamInHalAidl::read` |

这两个地址是本机实测值。换机型要重新测。

## 三、声音格式

| 环节 | 格式 |
| --- | --- |
| 出口抄到的 | 16 位整数，48000 赫兹，立体声 |
| 工具内部缓冲区 | 16 位整数，48000 赫兹，立体声 |
| 入口写回 | 16 位整数，采样率跟随该录音流 |

## 四、录音流的采样率

系统里同时有 16000 和 48000 两种录音流，都会经过同一个入口函数，而函数里的采样率字段在所有流上读到的是同一个值。

工具靠相邻两次调用的时钟间隔反推每条流的采样率，再吸附到标准值（8000、16000、44100、48000 等）。

## 五、用了哪些技术

| 层面 | 选择 |
| --- | --- |
| 手机界面 | Kotlin + Jetpack Compose |
| 装钩子 | 自带的 `mcinject`，用 ptrace 把载荷加载进声音服务 |
| 钩子本体 | `libmcpayload.so`，C 编写，无外部依赖 |
| 装法 | 在两个关口写一段跳转指令，处理器调用真实函数前恢复原字节 |
| 提权 | KernelSU 的 `su` |
| 构建 | GitHub Actions 云端构建 |
| 签名 | 固定密钥，存 GitHub 加密变量 |

## 六、钩子的写法

系统库带指针校验。把函数地址直接换成自己的会被拦下并崩溃，这一条实测过。

采用的写法是写跳转指令：

- 出口：`bti jc` + `ldr x16` + `br x16` + 处理器地址，占 16 字节；
- 入口：保留首条 `bti c`，从 `+4` 起写 `ldr x16` + `br x16` + 处理器地址，占 16 字节。

跳转指令只有几条，处理器在调用真实函数前把它们恢复成原字节，返回后再写回。两处各用一把自旋锁串行化。
